In progress

Renellence CRM

An in-house CRM to replace HubSpot

Renellence is moving from HubSpot to its own CRM, and I'm building it on a Postgres database. Leads, calls, emails, orders and payments come in through one intake pipeline, and the sales platform works directly with the company's own records.

Data model

A Postgres schema for contacts, clinics, deals, owners, files and change history. HubSpot records are imported with their history.

Intake pipeline

TypeScript functions on Supabase turn payments, orders, ad leads, emails and calls into CRM records through webhooks and scheduled pulls.

Shared write rules

Create, update and link logic lives in database functions, so the app and the intake pipeline write records the same way.

Rep-facing screens

Contact and clinic views, deal boards, tasks, filterable saved lists with CSV export, and Gmail connected through Google sign-in.

Careful migration

It's being built and tested in a separate sandbox alongside the live system, so the switch shouldn't disrupt the sales team.

Testing

Each intake source has its own tests, and the API is tested against an in-memory Postgres database.

Order automation

An n8n workflow that takes an order from intake through to delivery without manual re-entry.

  1. Order intake
  2. Approval by a person
  3. E-signature
  4. QuickBooks invoice
  5. 3PL shipment tracking
  6. Synced back to the CRM

Connects nine services, including HubSpot, Stripe, Shopify, QuickBooks and Meta.

Approach

Things I try to get right

Not losing data

Syncs don't delete anything until a copy is confirmed, and records are deduplicated.

Handling outages

Retries with backoff and cached fallbacks, so the app still works when a service is down.

Testing

About 1,600 assertions across 46 suites, with a local setup that mocks the outside services.

Careful releases

A dry run and a backup before each release, then a check that everything still runs.

Personal project · Oct 2026

yAI

A ChatGPT-style app that runs AI models on my own hardware. Its strongest model, Qwen 3.8 27B, runs on a 48 GB cloud GPU that only exists while someone is using it.

The site is on Vercel. Everyday models run on my laptop's 6 GB GPU: each question travels through a Cloudflare tunnel to a token-protected bridge in front of LM Studio. Qwen 3.8 27B runs on RunPod's serverless GPUs with vLLM. It shuts down to zero when idle, so a conversation costs about five cents, and the site switches to it automatically when my PC is off.

Qwen 3.8 27B streams at about 34 tokens per second and gets right the reasoning and fact questions the small models miss; the local models reach up to 200 tokens per second. I benchmarked eight models for speed and accuracy.

It also makes images and videos on serverless ComfyUI GPUs. Qwen-Image 2.1 creates pictures from a description or edits a photo you upload, and MiniMax H3 turns a prompt or a photo into a short video with sound. Everything goes through a safety filter and daily limits. Accounts, saved chats, images and videos are stored in Upstash Redis, so everything works even when my PC is off.

yAI Code brings the same models to the terminal: a coding agent like Claude Code that signs in with your yAI account and works inside your project folder. It reads and searches the files, edits them in place, and runs shell commands to build, test and lint the code. By default it asks before every file change and command, so nothing happens until you approve it.

yAI Code also gets a model of its own: Qwen3 Coder 30B, a coding model on a 96 GB VRAM cloud GPU. Like the 27B model, it runs on RunPod with vLLM and shuts down to zero when idle. It's a mixture-of-experts model that uses only 3 billion of its 30 billion parameters for each token, so it's quick for its size. The web app lists it too, greyed out, because it only works inside yAI Code.

It has three permission modes: ask prompts before any edit or command, accept-edits applies file changes automatically but still asks before running commands, and plan is read-only, so it explores the codebase and proposes a step-by-step plan without touching anything. You can @-mention specific files to point it at the right place, and each project folder keeps its own saved conversations, so picking up a project later resumes right where you left off.
